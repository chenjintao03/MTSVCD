# Running the codec projects

## Source and environments

`Deep Learning-based/DCVC-RT` and `Deep Learning-based/DCVC-TCM` contain the
server codec sources, their original licenses, and build instructions in
`UPSTREAM_README.md`. The RT project includes its local differentiable training
path. The TCM fine-tuning adapter is under `experiments/tcm_matched/code/`.

`metadata/runtime_versions.json` records the captured Python/package versions.
RT used Python 3.12.16 and PyTorch 2.6.0+cu126; TCM used Python 3.11.15 and
PyTorch 2.6.0+cu126. Install dependencies and build the C++/CUDA extensions for
the corresponding environment using the retained project instructions.

Download the original pretrained models using the instructions in each
project's upstream README. RT requires `cvpr2025_image.pth.tar` and
`cvpr2025_video.pth.tar`. TCM requires the four paired
`intra_psnr_TMM_q*.pth.tar` and `inter_psnr_TMM_q*.pth` models.

## Workspace preparation

1. Download MTSVCD and validate its fixed split with
   `python tools/validate_splits.py --dataset-root /path/to/dataset`.
2. Copy `configs/paths.example.json` to a configuration outside Git and set the
   dataset, pretrained-model, Python-environment, and workspace paths. Set the
   UUIDs for physical GPUs 4 and 5 using
   `nvidia-smi --query-gpu=index,uuid --format=csv,noheader`.
3. Use a new, empty workspace outside the checkout. On Windows/WSL, keep
   generated inputs, metrics, logs, caches, reconstructions, bitstreams, and
   checkpoints on D: / `/mnt/d/dataset`.
4. Render the source/configuration templates:

```bash
python tools/prepare_experiments.py --config /path/to/local_paths.json
```

Preparation does not start models or certify experiment gates. The official
Vimeo split lists are copied from the configured local Vimeo dataset when
present. UA-DETRAC and ShanghaiTech require their separately obtained data;
their training manifests are generated by the corresponding preflight code.

## Local input manifests and workflows

Generate the native-YUV420 test inputs and their checksums locally:

```bash
python tools/prepare_test_inputs.py --config /path/to/local_paths.json
```

The test-window rule is three 96-frame windows per test video: beginning,
middle, and end. There is no resizing or RGB round trip. The tool records input
identities in the workspace. `--limit 1` is an extraction smoke check and writes
only a preview manifest; a full manifest is written after all 246 windows are
prepared.

The retained workflow directories provide RT/TCM adaptation, four-dataset RT
comparisons, validation selection, and native-YUV420 evaluation. Their
`protocol/experiment.json` and `benchmark.json` files describe the settings.
The staged controllers require locally generated input/model/gradient gates,
preceding baseline results, and any dataset-specific manifests before later
steps. Cross-dataset input manifests must be prepared for the local datasets.
The source fingerprints in the release and rendered workspace identify the
respective source versions; old pass markers are not substituted for new gates.

Experiment input manifests, per-video records, and checkpoint/runtime records
are not distributed in the public presentation. The [project README](../README.md#experimental-results)
shows representative paper figures. The dataset's train/validation/test lists
and necessary sequence metadata remain available under `splits/` and `metadata/`.
